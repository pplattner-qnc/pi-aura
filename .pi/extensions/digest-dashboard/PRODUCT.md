# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Any Aura user checking up on what needs their attention. They open the dashboard to see, in one glance, what's overdue, what's waiting on them, today's committed queue, capacity, and reviews — then act on it.

## Product Purpose

A stable, single-screen daily digest of what needs your attention in Aura. It consolidates attention items, today's queue, capacity, and reviews into one scannable view, with one-click suggested actions that loop back into the pi agent as instructions — closing the gap between *seeing what to do* and *starting to do it*.

## Positioning

Two things a neighboring product could not copy together: (a) a **stable digest** — the Aura UI changes constantly, but this surface stays a consistent daily briefing; and (b) a **direct loopback into the agent** — suggested actions are dispatched into pi as agent instructions, not just read.

## Operating Context

Part of the pi-aura morning routine. In production it is served by a detached dumb file server that reads a generated digest and pushes hot-reload via SSE on `/events`. In live preview it is a Vite dev entry (`live/index.html`) that stubs `/api/digest` with a fixture and swallows `POST /api/state`, so the UI can be iterated without the detached server. The user reads the digest, scans the queue, checks capacity and reviews, then clicks a suggested action to hand work to the agent.

## Capabilities and Constraints

- Single-user surface; reads the digest from `GET /api/digest`, posts action clicks to `POST /api/state` as `action_click` state events.
- Live hot-reload via `EventSource("/events")`; each message re-fetches the digest.
- Sections: Summary (with stale corrections), Needs your attention (overdue / waiting on you / waiting on others / since-last-run / older unread), Today's queue (rank, task, status, role, capacity %, hours, git summary, with committed totals), and a bottom tabbed panel — Capacity / Reviews due / Reviews owed / Suggested actions.
- Suggested actions are disabled once one is active (the user is "working" it); the active one shows a spinner + "Working…" badge.
- Capacity assumes an 8-hour workday; hours = capacity% × 8, rounded to ¼h.
- Dev fixture lives at `live/digest.json`; the production digest is generated by the morning-fetch pipeline.

## Brand Commitments

No binding brand, voice, or visual identity is locked. The current look (Tailwind v4 + daisyUI utility classes, emoji status badges, neutral card surfaces) is incumbent scaffolding, **not** a commitment. One explicit scope constraint: **keep the Tailwind/daisyUI stack and the existing component structure, and refine the visual layer (spacing, hierarchy, polish) — do not redesign from scratch.**

## Product Principles

1. **One screen, one glance.** The whole briefing fits a single scannable viewport; depth lives in scroll, not navigation.
2. **Stable over fresh.** The surface's structure is the stable constant the Aura UI is not; resist novelty that erodes that reliability.
3. **Reading leads, acting follows.** The digest is for comprehension first; actions are the lightweight loopback, not the centerpiece.
4. **Scannable density.** Capacity, queue, and attention are dense but ordered — tabular where it aids comparison, never cluttered.
5. **Refinement, not reinvention.** Improve the existing identity in place; do not swap it for a different visual world.
