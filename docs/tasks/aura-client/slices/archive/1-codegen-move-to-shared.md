## End-to-end behavior

The `@hey-api/openapi-ts` codegen setup moves from `scripts/` into
`packages/shared/`. The generated REST client is produced at
`packages/shared/src/generated/` (gitignored, regenerated by `make codegen`).
`packages/shared` owns the generated client; the `@hey-api/client-fetch`
runtime dep + `@hey-api/openapi-ts` devDep live in the shared package's
`package.json` (single-source per grilling Q27). The `Makefile` `codegen`
target runs the codegen in `packages/shared`.

## Acceptance criteria

- `packages/shared/openapi/openapi.yaml` exists (moved from
  `scripts/openapi/openapi.yaml`).
- `packages/shared/openapi-ts.config.ts` exists (moved from
  `scripts/openapi-ts.config.ts`), with `input`/`output` paths adjusted to
  the new location (`input: "openapi/openapi.yaml"`,
  `output: "src/generated"`).
- `packages/shared/package.json` gains:
  - `dependencies`: `@hey-api/client-fetch` (single-source runtime dep).
  - `devDependencies`: `@hey-api/openapi-ts` (codegen).
  - a `codegen` script: `openapi-ts -f openapi-ts.config.ts`.
- `packages/shared/src/generated/` is produced by `make codegen` (or
  `cd packages/shared && npm run codegen`) and is gitignored (add
  `src/generated/` to `packages/shared/.gitignore`).
- The `Makefile` `codegen` target runs the codegen in `packages/shared`
  (not `scripts`); `gen` (codegen + typecheck + build) still works.
- `npm run typecheck` in `packages/shared` passes (the generated tree
  type-checks, now that it's in the shared package with `@hey-api/client-fetch`
  as a dep).
- `npm install` at root succeeds; `@hey-api/client-fetch` resolves from the
  hoisted `node_modules`.

## Test plan

- Seams: the codegen must produce `packages/shared/src/generated/` with
  `sdk.gen.ts`, `types.gen.ts`, `client.gen.ts`, `index.ts` (same shape as
  the existing `scripts/src/generated/`). Verify with `make codegen` then
  `ls packages/shared/src/generated/`.
- Failure modes: a wrong `input`/`output` path in `openapi-ts.config.ts`
  makes codegen fail or write to the wrong dir — verify the output lands in
  `packages/shared/src/generated/`.
- Scenarios: from a clean state (rm the generated dir), `make codegen`
  regenerates it; `cd packages/shared && npm run typecheck` passes on the
  generated tree.
- Edge cases: the generated `client.gen.ts` hardcodes
  `baseUrl: 'http://localhost:3000/api'` — that's fine; `createDefaultAuraClient()`
  (slice 3) overrides it. Do not edit the generated file.

## Constraints / dependencies

- None (this is the first slice; it creates the substrate the next two
  slices build on).
- The existing `scripts/src/generated/` and `scripts/openapi*` stay in place
  for now (dead after `call-site-migration`; removed in `clients-cleanup`).
  Do NOT delete them this slice — `scripts` still typechecks against the old
  tree until `call-site-migration` rewires it. (Two generated trees briefly
  coexist; only the shared one is used by `aura-client`.)
- `scripts/package.json` keeps `@hey-api/client-fetch` + `@hey-api/openapi-ts`
  for now (the old codegen still runs there until cleanup); the shared
  package gets its own copies (single-source applies to the *shared* package's
  consumers — scripts drops its copies in `clients-cleanup`).
