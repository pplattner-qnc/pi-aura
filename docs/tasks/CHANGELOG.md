## 2026-09-29: Persistent sqlite cache for reference autocomplete (reference-cache-sqlite)

Ticket 2 of 6 in the `unified-reference-mentions` map: the reference engine's production cache is now a persistent, cross-session sqlite store (`node:sqlite` `DatabaseSync`, WAL journal mode, `~/.pi/agent/aura-reference-cache.db`, one table keyed `(base_url, kind, id)` with `item_key`, `title`, `status`, a kind-agnostic metadata JSON column, and `fetched_at`), so autocomplete is instant in every pi session, not just warm ones; the in-memory cache stays the unit-test fake and the silent fallback. The TTL (`aura.references.cacheTtlMs`, global settings with a project `.pi/settings.json` override, default 6 hours) gates the session-start warmup only (within TTL and non-empty skips the fetch entirely; expired, empty, unstamped, or non-positive-TTL caches fetch) while reads stay stale-while-revalidate and the per-query refresh stays always-on. Writes coalesce as one `BEGIN IMMEDIATE` transaction per call (last-writer-wins per key, no torn batches) with a 500 ms default busy timeout whose timeouts are swallowed. Whole-ticket review found and fixed a real cross-session bug: SQLite does not invoke the busy handler for journal-mode switches, so sessions racing the first creation of the shared file silently fell back to in-memory and dropped their writes; the open sequence now retries bounded (5 attempts, linear backoff). Tests: 14 sections in the new `aura-reference-cache.test.ts` (including spawned cross-process writer races with integrity checks), the 35-section engine suite unchanged and green, root vitest 236, shared 202, all typechecks clean; the one red (`atlassian-provision.test.ts`) is pre-existing on develop and filed as a bug. All three deviation verdicts: conforms (recorded refinements: the store lives in its own module behind the dynamic-import seam, `fetchedAt(kind)` is derived as MAX over the kind's rows, the default TTL decision and the strict boundary semantics).
