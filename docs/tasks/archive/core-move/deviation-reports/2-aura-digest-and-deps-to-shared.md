## Deviation report — 2-aura-digest-and-deps-to-shared

> **NOTE — superseded by the orchestrator's coherence pass.** This report
> describes the tdd-worker's *original* implementation, which hand-patched 11
> generated SDK files with `.js` extensions and split `aura-client.ts` into a
> type/value re-export with a new `./aura-client-impl` subpath. The
> orchestrator replaced BOTH with a single clean fix: `packages/shared` now
> points codegen's `output.tsConfigPath` at a new `tsconfig.codegen.json`
> (`moduleResolution: NodeNext`), so `@hey-api/openapi-ts` emits `.js`
> extensions on generated relative imports natively (supported since
> openapi-ts v0.67). The generated tree is now codegen-fresh and survives
> `npm run codegen`; the `aura-client.ts` split was reverted as unnecessary
> (the original un-split single-export form works once the generated SDK's
> imports resolve under NodeNext). The findings below are preserved for the
> record but DO NOT reflect the committed state — see the task doc's
> `## Implementation notes` (slice 2 entry) for what actually landed.

### API surface changes

- **Planned:** `aura-digest.ts`, `devlinks`, `clients`, `mcp-client`,
  `bitbucket` move to `@pi-aura/shared/digest/*` with explicit export
  subpaths. `fetchAction`, `renderAction`, `saveAction`, `diffAction`,
  `cleanupAction`, `lastAction`, `USAGE` exported from
  `@pi-aura/shared/digest/aura-digest`. `scripts/src/aura-digest.ts` becomes
  a thin CLI shim importing the actions from shared. The `fail()` helper
  becomes a `throw new FailError(...)` in the core; the shim catches and
  preserves exit codes.
- **Actual:** All of the above was implemented exactly as specified.
  - The 5 modules moved with `git mv` (R100 — pure rename, 0 content change
    for `devlinks`, `clients`, `mcp-client`, `bitbucket`).
  - `aura-digest.ts` moved to `packages/shared/src/digest/aura-digest.ts`
    with the `fail()` → `throw new FailError()` seam and module-level
    `main().catch()` removed.
  - All 6 actions + `USAGE` + `FailError` are exported from
    `@pi-aura/shared/digest/aura-digest`.
  - The 5 new `./digest/*` export subpaths were added to
    `packages/shared/package.json`.
  - `scripts/src/aura-digest.ts` is now a 39-line thin shim importing the
    actions + `FailError` + `USAGE` from shared, dispatching on
    `process.argv`, and catching `FailError` to preserve exit codes.
  - Exit codes verified: `2` for missing/unknown action, `1` for
    no-last-digest — matches the arch spec decision.
  - The `fetchAction` cross-import seam (the gate for tasks 2–4) was
    verified: a scratch `import { fetchAction } from
    "@pi-aura/shared/digest/aura-digest"` in a temporary extension file
    typechecks under `tsc --noEmit` with no TS6059. (Probe deleted, not
    committed.)

- **Unplanned API surface addition (2 items):**

  1. **`./aura-client-impl` export subpath.** A new export subpath
     `@pi-aura/shared/aura-client-impl` → `./src/hey-api-aura-client.ts`
     was added to `packages/shared/package.json`. This is NOT in the arch
     spec's export map. It was created because the extension's
     `moduleResolution: NodeNext` follows value re-exports transitively:
     `@pi-aura/shared/aura-client` re-exports `createDefaultAuraClient`
     from `hey-api-aura-client.ts`, which imports the generated SDK
     (`./generated/client/client.gen.ts`), whose extensionless relative
     imports fail under NodeNext (TS2307/TS2834). The worker split
     `aura-client.ts`'s re-exports into **type-only** (stays at
     `./aura-client`) and **value** (moved to `./aura-client-impl`),
     then re-pointed the two runtime callers (`aura-digest.ts` in shared
     and `scripts/src/aura.ts`) to `@pi-aura/shared/aura-client-impl`.
     This was **necessary** to make the extension typecheck pass — without
     it, importing `fetchAction` from the extension transitively pulls in
     the generated SDK and fails. The split is well-documented with a
     `// rule: no-value-reexport-from-aura-client` comment explaining the
     rationale.

  2. **Generated SDK files patched with `.js` extensions.** 11 generated
     files under `packages/shared/src/generated/` had their internal
     relative imports patched from extensionless (`./client`) to `.js`
     (`./client/index.js`, `./types.gen.js`, etc.). These are
     auto-generated files (header: "This file is auto-generated by
     @hey-api/openapi-ts") that previously used extensionless imports
     which work under `moduleResolution: bundler` but fail under
     `NodeNext`. This was **necessary** for the same reason: the extension
     typechecks with `NodeNext`, and `fetchAction` transitively imports
     the generated SDK via `createDefaultAuraClient`. **Residual risk:**
     a future `openapi-ts` codegen run (`npm run codegen` in
     `packages/shared`) will overwrite these patches, reintroducing
     extensionless imports. The codegen config or a post-codegen patch
     step should be updated, but that is out of scope for this slice.

- **Impact on dependent slices:** The `fetchAction` export is available
  from `@pi-aura/shared/digest/aura-digest` — the gate for tasks 2–4 is
  met. The `./aura-client-impl` subpath is a new public API surface that
  tasks 2–4 may need to be aware of (if they import
  `createDefaultAuraClient` from the extension, they must use
  `@pi-aura/shared/aura-client-impl`, not `@pi-aura/shared/aura-client`).
  The `readDashboardUrl` export for slice 3 is unchanged (still at
  `@pi-aura/shared/digest/progress-emitter`).

### Out-of-scope changes

1. **`packages/shared/src/aura-client.ts` — value/type re-export split.**
   The re-exports at the bottom of `aura-client.ts` were changed from
   value re-exports (`export { HeyApiAuraClient, createDefaultAuraClient,
   AuraApiError }`) to type-only re-exports (`export type { ... }`), and
   a new `./aura-client-impl` subpath was added for the value exports.
   This is out of scope for the slice doc (which says "move
   aura-digest.ts + deps") but was **necessary** to achieve the slice's
   own acceptance criterion ("the extension's `tsc --noEmit` imports
   them without TS6059"). Without this split, importing `fetchAction`
   from the extension transitively resolves the generated SDK and fails
   under NodeNext. This is a **justified out-of-scope change** — the
   arch spec's "move verbatim" instruction couldn't anticipate the
   NodeNext transitive-resolution chain, and the worker correctly
   diagnosed and fixed it with a documented `// rule:` comment.

2. **`packages/shared/src/generated/` — 11 files patched with `.js`
   extensions.** These auto-generated files had extensionless relative
   imports that fail under `moduleResolution: NodeNext`. The worker
   added `.js` extensions to make them NodeNext-compatible. This is
   out of scope (generated files, not digest core) but was **necessary**
   for the same extension-typecheck reason. **Residual risk:** a future
   `openapi-ts` codegen run will overwrite these patches.

3. **`scripts/src/aura.ts` — one import re-pointed.**
   `createDefaultAuraClient` import changed from
   `@pi-aura/shared/aura-client` to `@pi-aura/shared/aura-client-impl`.
   This is a consequence of the value/type split (#1), not independently
   scoped. The `aura.ts` bundle builds and runs correctly.

4. **`test/` — 4 test files re-pointed.** Test imports of
   `../../scripts/src/bitbucket.js` / `clients.js` re-pointed to
   `@pi-aura/shared/digest/bitbucket` / `clients`. Necessary because the
   source files moved. Not a scope violation.

### The `fail()` seam

- **Matches the arch spec decision exactly.** `fail(msg, usage?, code)`
  now `throw new FailError(msg, usage, code)` instead of `process.exit`.
  `FailError` is an exported `Error` subclass with `readonly code: number`
  and `readonly usage: string | undefined`. The CLI shim catches
  `FailError` specifically: prints `e.message` + `e.usage` (if present),
  then `process.exit(e.code)`. Other errors fall through to the generic
  `console.error("aura failed: ...")` + `process.exit(1)` path.
- **Exit codes verified:**
  - `aura-digest.mjs` (no args) → exit `2` (FailError default code). ✅
  - `aura-digest.mjs bogus` → exit `2` (unknown action). ✅
  - `aura-digest.mjs last` (no store) → exit `1` (FailError code=1). ✅
- **Module-level `main().catch()` removed from shared core.** Confirmed
  — the shared `aura-digest.ts` has no `main()` call and no
  `process.exit`. The only `process.exit` reference in the shared core is
  in the `FailError` doc comment. ✅
