## Deviation report: remove-cli-rest-surface

### API surface changes

- **Planned:** Per the architecture's per-ticket graph, ticket 4 removes the bundled CLI, the scripts serving only it, the REST reference resource, the build and regeneration targets for them, and every doc passage teaching that access; the six dead review subcommands go with the CLI, no migration; the remnants guards are extended to pin the removed names. The exported contract to dependents is the guard-enforced absences plus the shrunken build surface.
- **Actual:** Delivered as specified, with the structural removal wider at one edge: the entire scripts npm workspace is deleted (package.json, tsconfig.json, esbuild.config.mjs, .gitignore, and all of scripts/src: aura.ts, the rest-* command modules, gen-rest-doc, gen-rest-index with the generated rest index, and their 10 suites), and the root package.json workspaces list is narrowed to `["packages/shared"]`. scripts/openapi-sync.sh and scripts/release.sh stay because they serve the shared package, whose REST library is the consumer-rule ticket's domain; a new guard assertion pins the Taskfile's codegen, openapi-sync, and typecheck targets present against over-deletion. The Taskfile loses gen-rest-doc and gen-rest-index and also build (bundle plus verify), watch, and clean, since nothing remains to bundle; `task gen` narrows to codegen plus typecheck, and typecheck covers packages/shared only. The guard (packages/shared/test/guards/no-remnants.test.ts) gains three sections (scripts-workspace absence, CLI-and-REST-reference removal, and a line-level CLI/REST-teaching pattern scan over skills/ plus the five root docs); the legacy scripts-workspace section was reworked from presence to absence assertions because it read the deleted manifest and would have crashed. No runtime module changed: extensions/ and packages/shared/src are untouched in the diff; the only shared-package change is the guard test file.
- **Impact:** Ticket 5 (rest-library-consumer-rule) counts consumers against the narrower workspace, and if it removes the REST library and its spec-sync/codegen targets it must also drop the new keep-target assertions (expected hand-off). Tickets 7 to 9 inherit files already free of CLI/REST teaching, and the teaching guard deliberately permits the phrasings they are sanctioned to use (REST-only capability labels, the non-teaching note that the REST API exists, reachable by the same PAT through REST). Ticket 10 inherits already-correct post-teardown statements in testing.md and dev-env.md. For every consumer of the testing protocol, the always list no longer runs the 10 scripts suites or `task build`, and `task typecheck` now covers one workspace.

### Abstraction usage

The architecture's existing-abstractions list names the remnants-style guards for pinning absences; all test changes landed in the consolidated guard `packages/shared/test/guards/no-remnants.test.ts` (the arch's guard seam), in its established describe-block style with its ROOT_DOCS reader. No new test files and no new abstractions were introduced.

Forced by acceptance criteria 1 and 4; the rest of ticket 10's worklist (install pin, MCP config example, credential story, glossary, README tables, em-dash sweep) stands.
- skills/core/engineering-foundation/SKILL.md was touched although ticket 6 deletes the directory: its fetch-a-node handoff pointed at the removed `aura.mjs wiki get`; criterion 1 binds every shipped file until the move-out lands.
- The capacity placement facts (readCapacity, updateTaskMemberCapacity, updateTaskMemberParticipation as the documented MCP primary path; company settings, the cross-member view, and the leadership overview as UI pointers) were applied to usecases/capacity-planning.md and process/capacity.md as the minimal truthful replacement for the deleted REST teaching, partially consuming the capacity rewrites owned by tickets 8 and 9; the scope semantics and the new capacity process model remain theirs.
- usecases/upload-documents.md was substantially rewritten although the architecture's usecase worklist says the file is verified current and stays: the aura.mjs upload walkthrough and the forbidden-MCP-tools table had to die under criterion 1, and the file now teaches MCP-with-context guidance instead.
- Availability-claim corrections were deliberately left to their owning tickets: usecases/task-management.md and process/roles.md still say owner and crew assignment is not available via MCP (the effort's scorecard says owner and crew search is back); only the REST pointers were stripped, so those files are CLI/REST-free but not yet current.
