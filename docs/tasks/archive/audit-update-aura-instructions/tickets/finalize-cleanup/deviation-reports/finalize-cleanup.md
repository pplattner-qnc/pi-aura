(2) The dead js-yaml dependency and @types/js-yaml devDependency leave packages/shared, the removal guard pins their absence, the dependency tree is clean. (3) packages/shared/src/index.ts's stale placeholder comment naming the retired AuraClient is replaced. (4) The em-dash sweep over comments and injected strings in the named files (all three interface modules, cursor-rules.ts, the two named test files, the Taskfile header line, local-provider.ts, aura-skill-instruction.ts, aura-tasks.ts), reworded, not blind-substituted. (5) docs/testing.md's mock-convention sentence attributes the factory hooks correctly (createInterface is the feedback factory's hook; the reference engine's are loadCredentials and createCache; logPath named) and the runtime-resolution phrasing is fixed in both the doc and the Taskfile comment. Export to dependents: none named; only the effort close-out and contract-refresh-d3886f06 follow.

- **Actual:** All seven landed, each with a new guard test, and the suite settles at 171 (197 minus the 35 tests of the four deleted embed suites, plus 9 new guard tests: the directory-wide flat-series ban, the js-yaml absence scan, the index.ts placeholder pin, the tree-bounds narrowing pin, the injection-hook attribution pins, the runtime-resolution pins, the embed-token ban, the embed-and-ML-dependency absence pin, and the em-dash sweep pin). The deviations from the letter:

  1. **aura-mcp-contract.ts keeps the em-dashes inside its verbatim contract data, the headline deviation.** The ticket's sweep names all three interface modules; the contract module was left untouched because every one of its em-dashes (eight characters across seven lines; the result doc's "7 em-dashes" counts lines) sits inside the `SHIPPED_AURA_MCP_TOOLS` strings, verbatim transcriptions of the live server's own tool and parameter descriptions. This review re-verified all three legs of the justification: (a) the provenance guard (extensions/aura-mcp-contract.test.ts) reads the gitignored introspection dump and asserts whitespace-normalized description equality, so rewording fails the suite (the dump carries the same em-dashes, 67 characters across 56 lines); (b) the contract self-check compares descriptions against the live server at every construction, so rewording fires permanent cosmetic-drift warnings, reintroducing exactly the drift-noise defect the review dispositioned into contract-refresh-d3886f06; (c) the strings are injected nowhere (the registration sends only the server name, url, headers, and its own em-dash-free description, verified in `decideAuraMcpRegistration`). Note the ticket's own criterion scopes the ban to "comments and injected strings", which the data block is neither, so the criterion as written is met; it is the sweep bullet's file list the implementer deviated from, and documented. The new em-dash guard therefore bans em-dashes in every named file plus the contract module outside its data block, with the exemption written into the guard itself and the ruling routed to contract-refresh-d3886f06, where the dump is re-recorded and the contracts re-transcribed anyway. The exemption's boundaries are guard-asserted (the data block's start and close must exist, so a rename of the export fails the suite rather than silently widening the exemption).

  2. **Two dependencies beyond the ticket's letter left with the embed fixtures:** @huggingface/transformers and onnxruntime-node, grep-verified sole consumer `src/embed/local-provider.ts`. Deleting the fixtures while keeping their dependencies would have recreated the exact dead-dependency defect the js-yaml finding names. Pinned absent by the new embed-removal guard test. The ticket text names only js-yaml for removal, so this is a scope extension, recorded in the result doc's divergence section rather than improvised silently.

  3. **docs/testing.md's mock-fidelity bullet was rewritten generically, beyond "no longer presents them as a runtime seam":** the `_embedRaw` token, the local-provider.test.ts references, the concrete tensor-shape example, and the "remaining guard" claim all went, replaced by a generic example and the general lesson (record the real output shape whenever a suite mocks an external library's return value). The guard bans the embed token in that doc outright. The first GREEN edit tripped the new ban itself (the rewritten example still said "local-embeddings"), so the bullet was generalized a second time; the durable cost is that the specifics of the `_embedRaw` lesson now live only in git history, not in any shipped doc.

  4. **The guard supplements rather than rewrites the old flat-series ban:** the pre-existing workflow-phases.md-only assertion survives unchanged beside the new directory-wide describe. Harmless redundancy (the new test subsumes the old for that file), and the old test also carries the standard-series presence assertions the new one does not, so the supplement is the conservative choice.

  5. **"No js-yaml reference remains anywhere" was scoped to the shipped surface:** the guard scans extensions/*.ts, packages/shared/src and test (the guard file itself exempt as the enforcement record), Taskfile.yml, and both package.json files. The archived task docs under docs/tasks/archive/ still name js-yaml on 11 lines across 7 files as historical record, and the gitignored scratch files carry the token too; both are outside every guard's scope and correctly so (history is not teaching), but a literal grep of the tracked tree for js-yaml does not return zero.

  6. **local-provider.ts, named in the sweep list, was deleted by finding 7 rather than swept:** moot by the ticket's own structure (the same ticket removes the file), and the guard's comment records it so the enforcement record stays truthful about why a named file is not in the ban list.
