# Architecture spec — `aura-client`

> Shared across all slice chains. Stable once approved.

Task: `docs/tasks/aura-client/task.md`. Map: `aura-access-rewrite`.
Slices (each its own BFS level — strict sequential):

1. `codegen-move-to-shared` (size m)
2. `aura-client-interface` (size m, blocked by 1)
3. `hey-api-impl-and-factory` (size m, blocked by 2)

## Destination (from map + grilling decisions)

Scripts (`aura.ts`, `aura-digest.ts`) and the `/aura` extension will talk to
Aura's REST API **directly** via the generated `@hey-api/client-fetch` SDK,
behind an implementation-agnostic `AuraClient` interface with expressive
**domain** types (never generated types in the interface). The PAT comes
from the OS keyring (`@pi-aura/shared/keyring`); the instance base URL comes
from `~/.pi/agent/settings.json` `aura` block. The generated client moves
into `packages/shared/src/generated/` so `packages/shared` owns it
single-source (Q27). This task delivers the interface + impl + factory
**only** — call-site migration is the next task (`call-site-migration`).

Key decisions (from the map's "Decisions so far"):
- **Q8** generated types never leak into `AuraClient`; mapping lives in `HeyApiAuraClient`.
- **Q10** DI + factory: `HeyApiAuraClient({ keyring, baseUrl })`; `createDefaultAuraClient()` reads settings + builds keyring.
- **Q11** ~21 verbs (the exercised surface), not all 244 operationIds.
- **Q27/Q32** shared package declares `@hey-api/client-fetch` (runtime) +
  `@hey-api/openapi-ts` (codegen) once; exports `.ts` sources (no build step).
- **Q33** `Makefile` install is root `npm install` (workspaces root).

## Cross-cutting facts established

- Root `package.json` already declares `"workspaces": ["scripts", "packages/shared"]`.
- `packages/shared` exports `.ts` via `package.json` `exports`
  (`"./*": "./src/*.ts"`); consumers compile/bundle it themselves.
- `@pi-aura/shared/keyring` exports `Keyring`, `SecretKey`, `createKeyring`,
  `KeyringUnavailableError`, `KeyringLockedError`, `KeyringDBusError`.
  `SecretKey = { service: "aura"; name: "pat" }`.
- The Aura REST API base URL (e.g. `https://aura.dev-anwalt.de/api`) is
  **distinct** from the MCP endpoint (`https://aura.dev-anwalt.de/mcp`).
  The generated `client.gen.ts` hardcodes `baseUrl: 'http://localhost:3000/api'`
  — `createDefaultAuraClient()` overrides it.
- `@hey-api/client-fetch@0.13` usage: `createClient({ baseUrl })` returns a
  client; attach the bearer token via `client.interceptors.request.use((req) => { req.headers.set('Authorization', \`Bearer <pat>\`); return req; })`;
  pass `{ client, ...params }` to each generated SDK function to override the
  default instance. Generated SDK responses are `{ data, error, response }` —
  unwrap `data` and throw on `error`.

## Slice 2 — `aura-client-interface`

### Exports (planned public API surface)
`packages/shared/src/aura-client.ts`, importable as `@pi-aura/shared/aura-client`
(via the existing `"./*": "./src/*.ts"` exports map — no `package.json` change
needed for the path; add an explicit `"./aura-client": "./src/aura-client.ts"`
entry for clarity/discoverability).

Exports:
- `AuraClient` interface — ~21 methods (the exercised verbs).
- Domain types for every method's input and output — named for the domain,
  not the generated schema. See "Domain type catalogue" below.
- `createDefaultAuraClient()` is **not** in this slice (it's slice 3); this
  slice is interface + types only.

### The ~21 methods (signatures, domain types)

```ts
export interface AuraClient {
  // artifacts
  getArtifact(id: string): Promise<Artifact>;
  mcpCreateArtifact(input: CreateArtifactInput): Promise<Artifact>;
  mcpUpdateArtifact(input: UpdateArtifactInput): Promise<UpdateArtifactResult>;
  // knowledge / wiki
  getKnowledgeNode(uuid: string, opts?: { includeBody?: boolean }): Promise<KnowledgeNode>;
  getKnowledgeNodeByPath(spaceSlug: string, path: string, opts?: { includeBody?: boolean }): Promise<KnowledgeNode>;
  saveKnowledgeNodeBody(input: SaveKnowledgeNodeBodyInput): Promise<KnowledgeNode>;
  mcpWikiSearch(input: WikiSearchInput): Promise<WikiSearchResult>;
  getKnowledgeTree(spaceSlug: string): Promise<KnowledgeTree>;
  createKnowledgeNode(input: CreateKnowledgeNodeInput): Promise<KnowledgeNode>;
  // upload documents
  mcpCreateUploadDocument(input: CreateUploadDocumentInput): Promise<UploadDocument>;
  mcpGetUploadDocument(id: string): Promise<UploadDocument>;
  // boards
  getBoardBriefing(opts?: { locale?: string; refresh?: boolean }): Promise<BoardBriefing>;
  getBoardSummary(): Promise<BoardSummary>;
  // notifications
  listNotifications(opts?: ListNotificationsInput): Promise<NotificationList>;
  // my board
  getMyPriorityQueue(): Promise<PriorityQueue>;
  getMyCapacity(): Promise<Capacity>;
  // lists
  listArtifacts(opts?: ListArtifactsInput): Promise<ArtifactList>;
  listTasks(opts?: ListTasksInput): Promise<TaskList>;
  // reviews / approvals
  getArtifactApprovals(id: string, opts?: { version?: number }): Promise<ArtifactApprovals>;
  getTaskByHumanKey(key: string): Promise<Task>;
  getArtifactReview(id: string): Promise<ArtifactReview>;
}
```

> Exact method count ≈ 21 (the grilling's "exercised surface"). The two
> `listTasks` calls in `aura-digest.ts` differ only by query args — one method
> covers both. `mcpGetArtifact` vs `getArtifact`: the scripts call `getArtifact`
> (the non-MCP REST path returns `ArtifactDetail`); the interface exposes it
> as `getArtifact`. If the worker finds the generated SDK has both
> `getArtifact` and `mcpGetArtifact`, prefer the one the scripts actually call
> (`getArtifact`) and note it in the deviation report.

### Domain type catalogue (expressive, not generated)

The interface declares these from scratch (no `import` from `./generated/*`).
Fields are the subset the scripts actually read + the structurally required
ones; loose tails use a bounded index signature where the API is genuinely
open-ended (mirrors `scripts/src/types.ts`'s defensive style). The worker
should cross-check each type against `scripts/src/types.ts` (the existing
response shapes) and `scripts/openapi/openapi.yaml` (the required fields).

- `Artifact` — `{ id, title, latest_version, version, body, summary: string|null,
  kind: ArtifactKind, created_at, updated_at, ... }` (from `ArtifactDetail`;
  scripts read `body`, `title`, `current_version`/`latest_version`, `kind`).
- `ArtifactKind` — `"PLAN" | "REVIEW" | "GENERIC"`.
- `CreateArtifactInput` — `{ title, body, summary?, kind? }` (from
  `McpCreateArtifactRequest`).
- `UpdateArtifactInput` — `{ id, mode: "section"|"whole", body, summary?,
  target_heading?, expected_version?, confirm_full_replace? }` (from
  `McpUpdateArtifactRequest`; `id` is the path param).
- `UpdateArtifactResult` — `{ status, id, title, version, mode, affected_heading }`
  (from `McpUpdateArtifactResponse`).
- `ArtifactList` — `{ items: ArtifactListItem[]; pagination: Pagination }`.
- `ArtifactListItem` — `{ id, title, latest_version, created_at, updated_at,
  kind, pending_for_me, ... }` (from `ArtifactListItem`).
- `KnowledgeNode` — `{ id, space_id, space_slug?, kind: KnowledgeNodeKind,
  title, slug, latest_version, body?, ... }` (`body` present for documents;
  from `KnowledgeNode`).
- `KnowledgeNodeKind` — `"FOLDER" | "DOCUMENT" | "FILE"`.
- `SaveKnowledgeNodeBodyInput` — `{ uuid, body, summary? }` (from
  `KnowledgeNodeBodySave` + the path uuid).
- `WikiSearchInput` — `{ query, space_slug?, limit? }`.
- `WikiSearchResult` — `{ items: WikiSearchHit[] }`; `WikiSearchHit` —
  `{ id, space_slug, space_kind, title, url, heading_path: string[],
  excerpt, match_source }`.
- `KnowledgeTree` — `{ space_id, nodes: KnowledgeNode[] }`.
- `CreateKnowledgeNodeInput` — `{ space_slug, kind: "FOLDER"|"DOCUMENT",
  title, slug, parent_id?, order? }` (from `KnowledgeNodeCreate`; the scripts
  pass `space_slug` + `kind: "DOCUMENT"`).
- `UploadDocument` — `{ id, filename, mime_type, byte_size?, summary?,
  page_count?, ingest_status?, portal_url, pages: { page_number?, content? }[] }`
  (from `McpUploadDocumentDetail`).
- `CreateUploadDocumentInput` — `{ filename, content_base64, mime_type? }`
  (from `McpCreateUploadDocumentRequest`).
- `BoardBriefing` — `{ text?, generated_at?, ... }` (loose; scripts read `text`).
- `BoardSummary` — `{ overdue?: BoardBucket; waiting_on_me?: BoardBucket;
  waiting_on_others?: BoardBucket }`; `BoardBucket` — `{ count, items: BoardItem[] }`;
  `BoardItem` — `{ kind?, task?: { uuid, human_key, title, status, status_type },
  title?, since?, waiting_days?, link?, approvals_pending?, ... }` (from
  `BoardSummary`/`BoardAttentionBucket`/`BoardAttentionItem`; scripts read
  `task.human_key`, `task.title`, `title`, `waiting_days`, `since`, `link`,
  `approvals_pending`).
- `NotificationList` — `{ items: Notification[]; pagination: Pagination }`;
  `Notification` — `{ id, type, read, created_at, [k: string]: unknown }`
  (polymorphic; kept loose like `scripts/src/types.ts`).
- `ListNotificationsInput` — `{ limit?, sort_by?, sort_dir?, page? }`.
- `PriorityQueue` — `{ items: PriorityQueueItem[]; total, unordered_count }`;
  `PriorityQueueItem` — `{ id, human_key, title, status, status_type, level?,
  block, rank?, asap, blocked_by: string[], context_path: HumanKeyRef[],
  governing_date?, capacity_percent? }` (from `MyPriorityQueue`/the existing
  `AuraPriorityQueueItem`).
- `HumanKeyRef` — `{ id, title, level }` (from `AuraHumanKey`).
- `Capacity` — `{ base_percent, committed_percent, free_percent,
  utilization_percent, over, base_capacity_note?, tasks: CapacityTask[] }`;
  `CapacityTask` — `{ task_id, human_key, task_title, task_status, roles: string[],
  capacity_percent?, task_level?, hierarchy_path: HumanKeyRef[] }` (from
  `CapacityPersonal`/`AuraCapacity`).
- `TaskList` — `{ items: Task[]; pagination: Pagination }`.
- `Task` — `{ id, human_key, title, description, status, status_type, level?,
  ... }` (from `TaskListItem`/`TaskDetail`; the dev-links feature reads
  `jira_issues` off the detail — include `jira_issues?:
  { issue_key, summary? }[]` and `children?: { human_key, title? }[]` on `Task`
  since `getTaskByHumanKey` returns the detail).
- `ListTasksInput` — `{ role?, view?, status_slug?, limit?, page?, sort_by?,
  sort_dir?, status?, archived?, search?, tags?, level?, ... }` (the scripts
  pass `role`, `view`, `status_slug`, `limit`).
- `ArtifactApprovals` — `{ version, latest_version, decided_count,
  total_required, open_reviews: OpenReview[]; decisions: ApprovalDecision[] }`;
  `OpenReview` — `{ user_id, user_name, decided }`; `ApprovalDecision` —
  `{ user_name, decision, decided }` (from `ArtifactApprovalsResponse`; maps
  to the existing `ArtifactApprovalState`/`ArtifactApprovalDecision`).
- `ArtifactReview` — `{ version, review_state, reviewers: ReviewerStatus[],
  review_artifacts: { title? }[], initiator: { user_id, user_name } | null,
  review_started_at?, review_deadline_at?, is_initiator }` (from
  `ArtifactReviewOverview`; maps to the existing `ArtifactReview`).
- `ReviewerStatus` — `{ user_id, user_name, status, ... }`.
- `Pagination` — `{ page, limit, total, ... }` (the generated `Pagination`
  shape; a small shared type, declared once in `aura-client.ts`).

> The worker should **not** over-encode every nullable field; the goal is
> "expressive enough that call sites don't reach for `unknown`/`any`", not a
> 1:1 mirror of the OpenAPI schema. Where `scripts/src/types.ts` already has
> a close shape, reuse the field set (the `call-site-migration` task dedupes
> these later).

### Existing abstractions to use
- `scripts/src/types.ts` — reference for the response shapes the scripts
  already consume (the domain types overlap; the migration task dedupes).
- `scripts/openapi/openapi.yaml` component schemas — ground truth for
  required fields + enums (now at `packages/shared/openapi/openapi.yaml` after
  slice 1).
- The existing `packages/shared/package.json` `exports` `"./*"` pattern —
  `@pi-aura/shared/aura-client` resolves automatically; add an explicit
  `"./aura-client": "./src/aura-client.ts"` entry for clarity.

### Do NOT reimplement
- Do not import any type from `./generated/*` in `aura-client.ts` — Q8
  (generated types never leak into the interface). The interface is pure
  hand-written domain types.
- Do not add `createDefaultAuraClient()` or `HeyApiAuraClient` here — slice 3.
- Do not move/delete `scripts/src/types.ts` — the migration task dedupes it.

### Interface contract (for slice 3)
Slice 3 imports `AuraClient` + all the domain types from `./aura-client.js`
and implements `HeyApiAuraClient implements AuraClient`. The domain types are
the **only** vocabulary `HeyApiAuraClient`'s public methods expose; it maps
them to/from generated types in private helpers. If slice 2 discovers a verb's
input/output can't be expressed without `unknown` (genuinely polymorphic, e.g.
`getKnowledgeTree` returning a recursive tree), it declares a structural type
and flags it in the deviation report rather than reaching for `any`.

## Slice 3 — `hey-api-impl-and-factory`

### Exports (planned public API surface)
`packages/shared/src/aura-client.ts` **gains** (re-exports from a new impl file
or directly adds):
- `class HeyApiAuraClient implements AuraClient` — constructor
  `({ keyring: Keyring; baseUrl: string })`.
- `createDefaultAuraClient(): Promise<AuraClient>` — the factory.

(Keep `AuraClient` + domain types exported from `aura-client.ts`; the impl
can live in `aura-client.ts` or a sibling `hey-api-aura-client.ts` — worker's
choice, but the `@pi-aura/shared/aura-client` import path must surface both
the interface/types and the impl/factory. A sibling file re-exported from
`aura-client.ts` keeps the interface file clean; recommended.)

### `HeyApiAuraClient` design
- Constructor builds a private `createClient({ baseUrl })` from
  `@hey-api/client-fetch` (the runtime dep added in slice 1) and registers a
  request interceptor that sets `Authorization: Bearer <pat>`.
- PAT handling (respects the AC's `{ keyring, baseUrl }` constructor shape):
  - The constructor is synchronous; it stores `keyring` + the built client.
  - The PAT is read **lazily** from the keyring on the first request
    (`keyring.getSecret({ service: "aura", name: "pat" })`), cached on the
    instance, and reused for subsequent requests.
  - If the keyring returns `null`, the method throws a clear error pointing
    the user at `/aura secrets discover`.
- Each of the ~21 methods:
  1. maps its domain input → the generated SDK function's params/ body shape
     (private helpers, e.g. `private mapCreateArtifact(input)`);
  2. calls the matching generated SDK function from `./generated/sdk.gen.js`,
     passing `{ client: this.client, ...generatedParams }` (the `client`
     option overrides the default instance + its hardcoded baseUrl);
  3. unwraps the `{ data, error, response }` shape — returns `data` mapped
     to the domain output type, and throws on `error` (include status +
     message).
- Generated types appear **only** inside `HeyApiAuraClient` (private helpers);
  the public method signatures use the slice-2 domain types (Q8).

### `createDefaultAuraClient()` design
- Reads the `aura` block from `~/.pi/agent/settings.json` via a settings
  reader. **Settings move:** the `AuraSettings` interface gains a new
  `baseUrl?: string` field (Q4 — the REST API base URL, e.g.
  `https://aura.dev-anwalt.de/api`). The settings reader lives in
  `packages/shared/src/settings.ts` (moved from `scripts/src/settings.ts`,
  or a thin shared copy; the migration task reconciles). For this slice,
  add a minimal shared settings reader that returns `{ baseUrl?: string }`
  and have the factory throw a clear error if `baseUrl` is absent (point at
  the `aura.baseUrl` field in settings.json). Do not break
  `scripts/src/settings.ts` (scripts still imports its own copy until
  `call-site-migration`).
- `const keyring = await createKeyring();`
- `const pat = await keyring.getSecret({ service: "aura", name: "pat" });`
  — throw a clear, actionable error if missing (point at
  `/aura secrets discover`).
- `return new HeyApiAuraClient({ keyring, baseUrl });`

> PAT-read timing: the factory validates the PAT is present up front (clear
> early error). `HeyApiAuraClient`'s lazy PAT cache will re-read on first
> call — that double keyring read is acceptable (the OS keyring caches).
> Alternatively the factory may pass the validated PAT into the constructor
> as an optional field if the worker prefers to avoid the double read; the
> AC's `{ keyring, baseUrl }` shape is the minimum, an optional `pat` is a
> permissible refinement. Flag the choice in the deviation report.

## Open decisions (flag in deviation reports, don't block)

1. **Settings home:** does `settings.ts` move wholesale to `packages/shared`
   now, or does slice 3 add a minimal shared reader and the migration task
   reconciles? Recommendation: minimal shared reader this slice (just the
   `aura.baseUrl` field); full move in `call-site-migration`. The worker
   should not break `scripts/src/settings.ts`.
2. **Impl file layout:** `HeyApiAuraClient` + `createDefaultAuraClient` in
   `aura-client.ts` vs a sibling `hey-api-aura-client.ts` re-exported from
   `aura-client.ts`. Recommendation: sibling file (keeps the interface file
   clean); re-export so `@pi-aura/shared/aura-client` surfaces everything.
3. **PAT caching:** lazy-on-first-call (exact AC shape) vs factory-passed
   optional `pat` (avoids double read). Either is acceptable; flag the choice.
4. **`getArtifact` vs `mcpGetArtifact`:** the scripts call `getArtifact`
   (non-MCP REST path). If the generated SDK exposes both, use `getArtifact`
   and note it. The interface method is named `getArtifact` either way.
